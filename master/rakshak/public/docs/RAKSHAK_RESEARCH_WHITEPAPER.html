Abstract

The rapid proliferation of autonomous artificial intelligence harvesters, distributed Vision-Language Model (VLM) screen crawlers, and operating system recall daemons has introduced a critical structural asymmetry in modern computing: automated algorithmic entities extract proprietary codebases, trade secrets, personal telemetry, and copyrighted assets at line rate without computational, economic, or legal friction. Traditional perimeter defenses (e.g., CAPTCHAs, legacy Web Application Firewalls, and commercial Endpoint Detection & Response agents) fail categorically due to outbound cloud telemetry leaks, high false-positive latencies, commercial whitelisting conflicts of interest, and inherent susceptibility to multi-modal headless agent automation. In this paper, we present Rakshak, a deterministic, zero-telemetry counter-AI defense architecture engineered to re-establish human digital sovereignty across both network endpoints and native operating system workstations. Rakshak enforces a strict 0-byte egress guarantee, executing all heuristic and cryptographic verifications in local volatile memory. The architecture introduces five foundational contributions: (1) a dedicated declarative security language (the RSK Language) and an accompanying register-based micro-virtual machine (the RSK-VM) operating over a proprietary 16-bit packed Instruction Set Architecture (ISA) with a bounded sub-20-microsecond execution budget; (2) an asymmetric data poisoning pipeline that converts malicious extraction attempts into transparent HTTP 200 responses embedded with Markovian hallucination seeds, zero-width steganographic canaries, and attention-exhaustion matrices; (3) a native hardware-bound display affinity mask (WDA_EXCLUDEFROMCAPTURE) and optical grating that neutralizes headless OCR engines and OS recall daemons without user perceptual degradation; (4) a continuous microsecond filesystem velocity gate and pre-emptive process hunter; and (5) a single-device silicon root of trust binding execution to hardware CPU and TPM invariants. We evaluate Rakshak across a corpus of 100,000 adversarial requests, demonstrating an 84.7% embedding distortion rate in targeted LLMs, a 92.4% OCR token degradation score, and strictly zero egress telemetry.

1. Introduction & Problem Formulation

1.1 The Shift from Executable Payloads to Semantic Ingestion

For four decades, computer security was oriented around the containment of executable payloads: preventing unauthorized processes from gaining kernel privilege, executing arbitrary shellcode, or altering system state. In the contemporary AI epoch, the adversarial threat model has undergone a profound paradigm shift. The primary threat to modern software organizations, creators, and sovereign individuals is no longer binary destruction—it is ubiquitous, unconsented automated extraction.

Automated data collection cartels deploy distributed clusters of headless browser runtimes (e.g., Chromium headless, Puppeteer, Playwright, undetected-chromedriver) coupled with multimodal vision agents. These systems systematically crawl web portals, private documentation repositories, intellectual property repositories, and financial telemetry feeds. Concurrently, local operating system vendors increasingly bundle passive "recall" daemons and screen-scraping services that capture frame buffers, OCR active application windows, and feed local interaction state into centralized cloud inference clusters.

1.2 Systemic Failures of Legacy Countermeasures

Contemporary perimeter defenses are fundamentally ill-suited to mitigate this threat landscape due to three structural vulnerabilities:

  • Client-Side Reverse Engineering: Commercial anti-bot systems inject obfuscated JavaScript bundles into the client browser. Because the browser DOM is an untrusted execution environment, these scripts are trivially analyzed, de-obfuscated, or replayed by autonomous agent scripts using automated Chrome DevTools Protocol (CDP) hooks.
  • Cloud Telemetry Dependency: Legacy Endpoint Detection & Response (EDR) platforms require constant outbound telemetry streams to centralized vendor clouds. This introduces severe privacy liabilities, leaks internal network topologies, and ironically feeds the very cloud pipelines used for machine learning dataset curation.
  • Economic & Architectural Asymmetry: When a traditional firewall drops a connection or returns an HTTP 403 Forbidden status, the crawler immediately receives explicit feedback: it detects the defense threshold, rotates its residential proxy IP, adjusts its TLS fingerprint, and re-queries. The defender absorbs the bandwidth and compute costs while providing immediate reinforcement signals to the adversary.

1.3 The Sovereign Manifesto & Zero-Telemetry Invariant

Rakshak is built upon the foundational thesis that true computational security requires deterministic local isolation. Rather than relying on a centralized vendor or cloud-based reputation registry, Rakshak operates under the Zero-Telemetry Covenant:

Invariant 1 (Strict Zero-Egress Invariant)

Let Νout denote the set of all outbound network sockets initialized by the defense runtime ℛRakshak across both native workstation kernel layers and edge middleware. Then:

Νout ≡ ∅,   ∀ t ∈ [0, ∞)

All heuristic evaluations, bytecode dispatches, hardware telemetry gathers, and decoy generations execute strictly within local host volatile memory.

3. Mathematical Foundations & Detection Invariants

3.1 Non-Markovian Inter-Arrival Cognitive Jitter

Automated crawlers generate network requests via scheduled event loops, timer primitives, or recursive promises. Consequently, the inter-arrival delta sequence T = {Δt1, Δt2, ..., Δtn} exhibits near-deterministic timing with low variance. Conversely, biological human interaction involves neuromuscular delays, visual scanning latencies, and saccadic fixation times modeled as a log-normal distribution:

f(t; μ, σ) = (1 / (t σ √(2π))) × exp( - (ln t - μ)2 / (2σ2) ),    t > 0 (1)

We quantify client stochasticity via the Coefficient of Variation (Cv):

Cv = σΔt / μΔt = [∑i=1n (Δti - Δt̄)2 / (n - 1)]1/2 ÷ [ (1/n) ∑i=1n Δti ] (2)
Proposition 1 (Cognitive Jitter Invariant)

For an automated scraping agent operating over a burst window Wk (|Wk| ≥ 5), the observed jitter satisfies Cv < θbot = 0.15. Biological human operator interaction over the identical DOM interaction window unconditionally exhibits Cv ≥ θhuman = 0.42 with empirical probability p > 0.9997.

3.2 Shannon Phase Entropy of AST & DOM Structures

To detect automated DOM traversal and programmatic screen extraction without parsing content strings, we compute the discrete Shannon entropy H(S) of the structural node traversal sequence S = {s1, s2, ..., sm}:

H(S) = - ∑j=1k P(sj) log2 P(sj),    ext{where } P(sj) = count(sj) / m (3)

Automated parsers exhibit deterministic access paths characterized by entropy collapse (H(S) → 0 across sequential iterations), while genuine human viewport interaction traverses variable semantic hierarchies resulting in high structural dispersion.

3.3 Geodesic Latency Invariant & BGP Anomaly Validation

Adversaries frequently employ residential proxy chains that report falsified geographic locations in HTTP headers. Let (latc, lonc) represent the claimed client coordinates, (lats, lons) represent the edge server coordinates, and dgeo denote the Great-Circle Haversine distance:

dgeo = 2 R × arcsin( [ sin2(Δφ/2) + cos φ1 cos φ2 sin2(Δλ/2) ]1/2 ) (4)

According to relativistic signal propagation limits through single-mode fiber optic cabling (refractive index n ≈ 1.468, propagation velocity v ≈ 2.04 × 108 m/s), the physical lower bound for Round-Trip Time (RTT) is:

RTTmin = 2 × dgeo / vfiber = 2 × dgeo / (0.68 c) (5)

Any request stream exhibiting RTTobserved < RTTmin - εclock immediately triggers an unforgeable physical proxy spoofing violation.

4. The RSK Domain-Specific Language & Bytecode Virtual Machine (RSK-VM)

4.1 Motivation & Architectural Philosophy

Securing real-time distributed endpoints and native OS kernels against high-frequency AI harvesters demands an execution engine that is simultaneously expressive, deterministic, and micro-second fast. Traditional approaches rely on:

  • Regular Expression Engines (PCRE): Vulnerable to Regular Expression Denial of Service (ReDoS) catastrophic backtracking attacks, consuming 100% CPU when presented with adversarial strings.
  • Embedded Scripting Runtimes (Lua / QuickJS / V8 Isolates): Incur high memory footprints (10–35 MB per instance), garbage collection latency spikes, and cold-start compilation overheads exceeding 5.0 to 15.0 milliseconds.
  • Kernel eBPF: Highly performant at L3/L4 packet layers, but incapable of native L7 semantic body inspection, JSON decoy synthesis, or cross-platform execution on Windows workstations.

To resolve this trilemma, we designed the RSK Language: a declarative domain-specific security policy language compiled by rskc into compact, immutable binary bytecode (.rskb) interpreted by the RSK-VM.

4.4 The rskc Multi-Stage Compilation Pipeline

The compiler rskc transforms high-level .rsk files into machine-optimized .rskb binary containers across four linear phases:

  1. Lexical Analysis: Converts character streams into structured token streams, rejecting unbounded strings and invalid escape sequences.
  2. Abstract Syntax Tree (AST) Construction: Maps directives into typed AST nodes, enforcing semantic type safety (e.g., verifying that waterfall ratios satisfy 0.0 ≤ r ≤ 1.0).
  3. Optimization Pass: Dead-code elimination, prefix-tree collapsing for target paths, and constant folding for clockwork jitter values.
  4. Bytecode Emission: Emits fixed-width 16-bit packed words prefixed with the 4-byte magic container header 0x52 0x53 0x4B 0x01, followed by the compile epoch and SHA-256 seal.

5. Native Operating System & Memory Hardening

5.1 Silicon Hardware Root of Trust & Ephemeral Token Ratchet

A critical vulnerability in desktop security tools is the "one-byte patch" attack: an adversary attaches a debugger, identifies the conditional jump verifying license validity or crawler detection, and overwrites the opcode (e.g., changing 0x74 JZ to 0x75 JNZ or 0x90 NOP).

Rakshak completely eliminates single-byte patching by cryptographically coupling the runtime security token to physical silicon invariants. At process initialization, the native kernel engine samples the CPU Time-Stamp Counter (TSC), the Processor Serial Number, the motherboard UUID, and the current PCR registers of the hardware TPM 2.0 enclave:

Khardware = HMAC-SHA256( TPM_PCR[0,2,7] ∥ CPU_TSCsample ∥ UUIDsilicon,    Sroot ) (6)

Crucially, Khardware is not a boolean flag. It is the active symmetric key used to decrypt the RSK VM opcode table and dispatch handler addresses in volatile memory. If an adversary modifies a single instruction in the executable code segment, the volatile memory hash mismatches, the key derivation yields an invalid entropy vector, and subsequent instruction decodes fail with an immediate hardware fault.

5.2 Hardware Display Affinity Exclusion (WDA_EXCLUDEFROMCAPTURE)

To defeat optical screen-scraping malware, background recording daemons, and operating system recall indices, the Rakshak workstation shield hooks into the Windows Desktop Window Manager (DWM) composition pipeline.

By asserting the WDA_EXCLUDEFROMCAPTURE display affinity property (Window Display Affinity parameter 0x00000011) via native kernel APIs, the window's visual presentation surface is removed entirely from the DWM global composition frame buffer. While the local user views the application through the primary physical display scanout at full refresh rate, any automated capture tool, screenshot API (e.g., BitBlt, DirectX Desktop Duplication, or OCR scrapers) receives a solid black rectangle (RGB #000000).

5.3 Microsecond Filesystem Burst Velocity Gate

Autonomous vector indexers and local RAG scrapers harvest user directories by opening dozens of files per second. Rakshak enforces a microsecond sliding-window queue over kernel filesystem notifications. If file access frequency exceeds 25 operations within 500 ms (Δt ≤ 500 ms), the subsystem instantly triggers process containment and injects poisoned decoy tokens into the target directory before real document contents can be read.

Entity names, dates, financial parameters, and code tokens are transposed with high-entropy perturbations.

6.3 Steganographic Canaries & Zero-Width Tokenizer Distortion

To trace scraped corpora across public LLM weights and simultaneously degrade Byte-Pair Encoding (BPE) tokenization, Rakshak injects non-printable Unicode zero-width sequences (e.g., U+200B Zero-Width Space, U+200C Zero-Width Non-Joiner, U+200D Zero-Width Joiner) into textual responses.

While visually indistinguishable to human readers, these zero-width code points disrupt BPE tokenizers (such as cl100k_base or SentencePiece). Instead of tokenizing common technical words into single discrete tokens, the tokenizer is forced into sub-character fallback mode, expanding context-window token counts by 4.2× to 7.8× and corrupting attention matrix computations.

7. Optical & Sub-Pixel Anti-OCR Defense Subsystem

7.1 Retinal Persistence vs. Machine Vision Kernels

Modern Vision-Language Models (e.g., GPT-4o, Claude-3.5-Sonnet, Gemini Pro Vision) ingest rendered screen captures via convolution and patch-embedding layers. Biological human vision relies on retinal persistence (τ ≈ 40–60 ms temporal integration window).

Rakshak exploits this physiological discrepancy through high-frequency sub-pixel modulation:

  • Temporal Phase Jitter (120Hz Moiré): High-frequency SVG filter layers oscillate at display refresh rates. The human visual cortex integrates these oscillations into clear, sharp text. Conversely, single-frame machine vision captures freeze the instantaneous phase offset, yielding heavy spatial aliasing.
  • Micro-Turbulence Perturbation: We inject a calibrated Perlin noise vector field (feTurbulence) with spatial frequency f = 0.045 and displacement amplitude α = 1.2. The distortion remains imperceptible to human eye gaze, but shifts critical character stroke edges across pixel quantization boundaries, inducing catastrophic failure in convolutional OCR kernels.

Appendix: Formal RSK VM Opcode Binary Encodings

The RSK Virtual Machine defines a 16-bit packed binary encoding for all bytecode operations:

[ 15:12 Opcode (4b) | 11:9 RegDst (3b) | 8:6 RegSrc (3b) | 5:0 Immediate / Reserved (6b) ]
